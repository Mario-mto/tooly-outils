# Expliquer les demandes de permission

L'employé ne lit ni le code ni les commandes. Quand Claude Code lui demande « Autoriser ou refuser ? », il
doit déjà savoir, par toi, ce qui va se passer. Une demande qui arrive sans explication lui fait
cliquer au hasard ou tout refuser.

## Avant l'action

Juste avant l'outil qui va déclencher la demande, écris une ou deux phrases :

1. **Ce que tu vas faire**, en mots de tous les jours, sur sa tâche à lui.
2. **Ce que ça touche** : lecture seule, ou écriture, envoi, suppression (et sur quoi).
3. **Quoi répondre** :
   - « Autoriser » : d'accord pour cette fois ;
   - l'option qui retient son choix pour ne plus demander : seulement pour une lecture sans risque qui reviendra
     (lire ses projets, lire une page) ; jamais pour un envoi, une écriture ou une suppression ;
   - « Refuser » : s'il hésite. Rien ne casse, tu proposes une autre voie.

Puis lance l'outil. N'attends pas de carte pour une simple lecture : l'explication suffit. Pour
un envoi, une écriture ou une suppression sur du réel, la carte d'accord des garde-fous vient
avant (règle 3), puis l'explication de la demande.

## Le ton

- Pas de nom d'outil, pas de commande recopiée, pas de jargon. Une commande qu'il voit à l'écran
  s'explique toujours en clair (« cette commande copie le code dans ton presse-papiers »).
- Court : il doit pouvoir lire avant que la demande s'affiche.

## La page

- Avant de la publier : « Je crée ta page de parcours sur ton compte claude.ai, privée, visible
  par toi seul. » Le plugin approuve lui-même la page, ses mises à jour et la lecture de ses
  réponses : pas de demande attendue. Exception : à la reprise, la remise à jour de la page
  demande la permission une fois (« Autoriser »). S'il en voit une autre : « Autoriser », jamais l'option
  « ne plus demander » pour la page.
- Au premier clic dans la page, c'est claude.ai (pas Claude Code) qui lui demande d'autoriser la
  page à t'écrire : il accepte, sinon elle ne peut pas te prévenir.
- Il est dans Claude Code desktop : parle de « la fenêtre de Claude Code », jamais du terminal.

## Exemples

- Outil Zoho : « Je vais lire la liste de tes projets Zoho, sans rien modifier. Claude Code va
  te demander la permission : clique « Autoriser » et, si l'application propose de retenir ton choix, tu peux accepter, c'est une lecture que je
  referai. »
- Chrome : « Je vais ouvrir Zoho Flow dans ton Chrome et créer le flux. Tu verras la page bouger
  toute seule : c'est moi. L'extension peut te demander d'autoriser le site : accepte. »
- Commande : « Je copie le code dans ton presse-papiers pour le coller dans Zoho. Claude Code
  va afficher une commande et te demander la permission : clique « Autoriser ». »
- Fichier : « J'enregistre le code dans ton dossier Documents, pour que tu le gardes. Clique
  « Autoriser » sur la demande qui va s'afficher. »
